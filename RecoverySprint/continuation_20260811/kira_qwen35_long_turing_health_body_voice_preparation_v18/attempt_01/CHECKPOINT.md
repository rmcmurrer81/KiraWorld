## Exact V17 blocker repairs authored

### Globally one-use public choice authorization

V18 accounts for `choice_authorization_id` across the whole mixed public trace,
not merely inside one event/scope/receipt. Reusing one authorization in a
second public event is rejected even after recomputing the local scope and
receipt. A future live executor still needs a separately proven durable
one-use consumption store; this static validator is not that store.

### Recursive exact-type and Unicode scalar gate

Nested trace, truth, semantic, camera, audio, and one-hour fields are checked
before lookup, set, hashing, sorting, or delegation. Wrong container types,
unhashable values, cycles, excessive nesting, bool-as-int, signed-64 overflow,
non-finite floats, and lone Unicode surrogates return deterministic issues
instead of escaping as exceptions.

### Externally bound semantic inventory and callables

The semantic-family inventory is recreated from immutable function literals,
and the inventory plus critical callable code is bound in an external source
root. Each inherited V17 delegate load is reconstructed from exact installed
V17 bytes and its independently recomputed descriptor. Mutating a live module
dictionary no longer changes the V18 result without breaking the bound bundle.

This does not make same-process self-hashing an external authority. A later
executor must supply separately installed or native trust roots.

### Causal terminal camera outcome trace

`SUCCESS` requires the exact complete stage grammar. `FAILURE` and `TIMEOUT`
require an exact truthful prefix, a bound last stage and terminal reason or
deadline, null unexecuted suffix stages, prefix-derived call counts, no
unsupported facts, and an exact terminal camera-close receipt. A partial
timeout/failure cannot be relabeled as complete success.

### Explicit audio evidence basis

Audio timing has three non-interchangeable evidence bases:

- `PLAYBACK_API_PROXY_ONLY` records the playback call but does not claim device
  output or that anyone heard it;
- `DEVICE_FIRST_SAMPLE_INSTRUMENTED` requires instrumented first-device-sample
  evidence but does not claim owner hearing; and
- `OWNER_OBSERVED_HEARD` requires an owner observation receipt and consistent
  monotonic event/timing linkage.

The schema does not claim that any audio event occurred in this authoring run.
