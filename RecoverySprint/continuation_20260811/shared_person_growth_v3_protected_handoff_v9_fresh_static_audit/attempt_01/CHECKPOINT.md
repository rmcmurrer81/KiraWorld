   compiled authority id/public key verifies both author and independent
   modes. All sealed receipts are author-test receipts under the author-fixture
   key. `recipient_opt_in=true` and `revocable=true` are issuer assertions,
   not person signatures. The 40-field receipt has no person-owned consent
   receipt, consent provenance/time, revocation epoch, or revocation-registry
   binding, and the engine performs no revocation check.
2. **Decision and consumer identity are only caller-supplied byte hashes.**
   Independent mode does not parse an audit-decision schema or require an
   `ACCEPT` verdict. It does not bind the consumer pathname, stable object
   identity, loaded receiver module/process, or actual entrypoint. Any caller
   can present a passive copy of the signed consumer bytes.
3. **Ledger/anchor safety is pathname-based and same-directory.** Ledger,
   anchor, debt, and lock share one caller-visible directory. There are no
   stable directory/file identities, held directory chain, protected-DACL
   APIs, or platform-separated monotonic anchor. Check-then-pathname races and
   joint ledger/anchor rollback remain possible to same-account code, not
   only a Windows administrator.
4. **The consumer scan is incomplete and evadable.** It scans only Python
   below eight selected roots, silently skips parse/decode failures, omits 29
   root Python files including `chat_kira.py`, `chat_lisa.py`, and
   `voice_kira.py`, omits Avatar and other code/config/languages, and excludes
   every candidate-version prefix. Four scratch-only constructions using
   `format`, `bytes.decode`, `replace`, and an expression f-string all evade
   it.
5. **The installed package is not self-verifying or rebuildable at its own
   path.** Its test and seal verifier target the original author scratch tree;
   its manifest/contract still say it is not installed. Strict `/Brepro`
   compilation of the exact installed Kira source yields
