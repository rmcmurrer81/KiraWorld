## Blocking findings

### 1. Allowed-field private-payload smuggling and false truth

The author suite correctly rejects eight unknown private-payload keys, but it
does not test private content placed in an allowed field. `_text` permits any
nonempty trimmed UTF-8 text up to 256 bytes, including embedded controls. The
Creator compiler copies that text into the normalized request and then emits a
categorical no-private-payload truth value.

This conflicts with the exact validated-result routing policy: the Temporary
Creator may receive generalized public rules and schemas, not another person's
private memory, reflection, emotion, desire, relationship, consent, roots,
anatomy, or other private life under a renamed field.

An append-only successor must either:

1. replace all emitted caller free text with exact, control-free public catalog
   identifiers or independently bound public metadata; or
2. label the caller metadata as untrusted and remove every categorical claim
   that no private payload is included.

It must add same-field private memory, emotion, desire, relationship, consent,
anatomy, and private-root probes, not only unknown-key probes.

### 2. Deceased-variant cutoff contradiction is not bound

The current code validates a nonzero digest shape and a caller-provided
relation string. It does not bind the source record, branch event, deceased
status, or temporal ordering to a public catalog or protected verifier. The
accepted contradictory label proves that the normalized pre-fatal claim is not
established by the exact input boundary.

An append-only successor must bind an exact public source/branch record that
proves source identity, branch point, deceased status, temporal ordering, and a
strictly pre-fatal inherited-memory cutoff. Until that external binding exists,
the proposal must describe the entire cutoff as an unauthenticated caller
assertion and must not normalize it into a factual pre-fatal claim.
