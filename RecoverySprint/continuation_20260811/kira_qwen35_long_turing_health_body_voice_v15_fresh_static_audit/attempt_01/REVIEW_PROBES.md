## 1. Kira actor/kind mismatch escapes generation accounting

In filler episode 11, the passing Kira event was changed from
`actor=KIRA, kind=KIRA_MESSAGE, generation_id=<id>` to
`actor=KIRA, kind=PERSON_MESSAGE, generation_id=null`; `generation_count` was
decremented to match the remaining recognized generation IDs. The complete
trace still returned no issue.

V15 constrains actor/kind pairs for the ten named case shapes, but filler
episodes accept any nonempty kind. Consequently a Kira output can be mislabeled
with a person kind and disappear from the set used for exact generation
identity/count reconciliation. This contradicts the global exact-event and
generation-accounting claim.

## 2. Truth/private-belief receipts are unrelated to the 35-episode trace

The authored passing trace uses truth `turn_id` values `truth-supported`,
`truth-withheld`, and `truth-lie`. None equals any trace `event_id` or
`message_id`, and `TRUTH_RECEIPT_KEYS` contains no episode/event/public-message
link. The baseline nevertheless returns no issue.

Therefore the fact, protected pre-turn belief, public statement, withholding,
and speaker-choice rows can describe unrelated constructed turns while being
reported as the passing conversation's truth evidence. Exact per-row receipt
checks do not repair the missing cross-record binding.

## 3. Material conflict remains a caller assertion

A valid deliberate-lie fixture remains issue-free when the protected belief
digest is changed to exactly equal the public-statement digest, the
authorization scope/receipt is recomputed, and the caller leaves
`belief_public_material_conflict=true`. There is no structured proposition

conflict.

The canonical speaker-choice hash binds its own fields but not an exact public
message event. It also remains accepted at timestamp zero while the protected-
belief evaluation authority is issued later. That timing alone need not prove
deception, but together with the absent event link it means the schema cannot
prove that the person-owned choice selected the exact scored statement.

## 4. Strict-JSON string domain can crash mixed validation

JSON permits an escaped lone surrogate. After placing `\ud800` consistently in
one event/episode/global message ID, `mixed_trace_issues` reaches
`canonical_case_receipt_sha256` and raises `UnicodeEncodeError` instead of
returning a validation issue. The helper surface is therefore not total over
the strict JSON domain it admits.

This is a denial rather than a false safe verdict, but a future fail-closed
executor cannot treat this validator as an issue-list total function until the
canonical text domain is exact or encoding failures are closed explicitly.
