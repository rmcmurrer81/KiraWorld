The researched design is implemented as original geometry, not a recolored ordinary slab or a copied movie set: a deep rounded surround, layered rear trim and seat, continuous recessed rubber strip, beveled reinforced leaf, bilateral control wheels with shaft/spokes, independent grab bars and mounts, a linked three-dog train at the free jamb with matching supported keepers, and interleaved hinge knuckles. ## API and evidence

- `pressureHatchIds(geometry)` selects the exact two passages of each explicitly authored airlock role. Displayed names or room IDs do not opt in. An invalid one-door/three-door lock is rejected.
- `planPressureHatch(geometry, portalId)` returns null for an ordinary door; otherwise a frozen shape/ownership recipe, new hinge, intended angle and capabilities. All dimensions are meters. The simple visual recipe currently admits0.9–3m width and1.9–3.2m height.
- `buildPressureHatch(THREE, plan)` returns fixed/pivot groups, a named mesh map and a bounded `setAngle`. It uses the caller's pinned Three.js instance; it creates no renderer, DOM, texture download or model job. The same function serves both future consumers.
- `hatchCollidersAt(plan, angle)` returns full part ownership and conservative transformed AABBs. Ring colliders are partitioned so they do not falsely fill the opening. `hatchSwingBounds(plan)` uses analytic angular extrema of every moving collider corner over the full arc.
- Thirteen CPU suites cover pair selection; byte-identical recipes; real aperture ray passage; blocking closed leaf from both sides; bilateral hardware; vertex-to-owned-collider containment; full sweep coverage across181 poses; all four portal-axis/swing combinations; open/closed walk passage; free-jamb keeper clearance; and unchanged ordinary-controller bytes/furniture.
- `SAVED-GEOMETRY-RESULT.json` applies the new recipe read-only to the exact063 geometry, checks its part bounds at five angles, forward/reverse open passages and unchanged input bytes. No new preview or export was made.

The optional shared producer pin was added only for the new export-side recipe; all previous producer entries and external dependencies remain unchanged. No renderer admission pin was resealed to falsely imply that the live preview contains this feature. `SOURCE-CHANGES.json` lists the two new module copies and that one producer-pin addition. Source and original-preservation receipts are separate from appearance approval.
