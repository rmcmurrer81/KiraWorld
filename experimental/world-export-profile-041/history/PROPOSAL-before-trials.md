# Bounded generalization of authored habitat export041

Installed039 is correctly limited to one geometry digest.041 replaces that
arbitrary fixture identity with a narrow, testable eligibility profile. It remains
isolated; installed039 and all saved sources/previews are unchanged.

Read-only inventory found two saved research jobs. Only the original Mars job has
dimensioned blueprints, in revisions1 and2; both use the same schema with7 rooms
and6 openings. Therefore no independent second owner-created habitat is available
as acceptance evidence. No personal brief, research text or source geometry was
copied into this audit. The current compiler accepts4..8 function rooms plus a
circulation corridor; arbitrary games, real-place reconstructions and VR are
outside this change.

## Proposed eligibility contract

- Retain exact selected-job binding, research/blueprint/cache digests, pinned
  renderer/controller/Three files and all existing dependency checks.
- Require the authored single-level entry-chain and corridor-branch template,
  5..9 walkable rooms on floor0,2.5..4m heights, supported dimensions and explicit
  known habitat functions. The existing reserved `circulation` fallback remains.
- Recompile the exact bound blueprint through the current pure compiler. Compare
  the full rooms, primitives, colliders, supports, portals, routes, connectivity,
  provenance and unapproved-quality flags with the saved geometry. Changed
  structural content is held even when someone updated the geometry's file digest.
- Verify one circulation corridor, a0..2-room entry chain and direct branches.
  Reject duplicate connections, vertical/locked layouts and unsupported templates.
- Require unambiguous structural room ownership. The current renderer uses room
  ID prefixes; names such as `lab` and `lab_annex` could otherwise assign materials
  or groups to the wrong room. Hold them rather than silently guessing.
- Require each authored airlock to have exactly two source doors. Keep039's pair
  policy, leaf/collider ownership and independent Python verification unchanged.

Eligibility allows an export attempt; it does not declare success. The exact
authored equipment builder must still fit within its collision/render budgets,
and the real texture/GLB importer checks must pass before a ready package exists.
Failed placement/unsupported door geometry or exceeded budgets are held by the
existing builder, with incomplete output preserved. A later improvement may
surface more specific builder messages before creating an output directory.

The package records eligibility and validator/compiler digests. The exported
scene name becomes `Authored_habitat_scene` so a different supported layout is
not mislabeled as Original Mars. No appearance, geometry or interaction is invented.

## Evidence and remaining checks

35 mocked API/callback/cross-language tests pass. These include a new shape with a
different geometry digest and a rebound-but-inconsistent structure rejection.
15 pure profile tests cover unknown/missing roles, changed geometry/routes,
false quality claims, vertical/oversized layouts, ambiguous IDs, duplicate branch
portals, multiple circulation roles, a one-door airlock and room-count limits.

Four synthetic variants pass the actual authored equipment, spawn, collider and
metadata modules: base, renamed room IDs, a wider operations room and a translated
layout. Each has7 rooms,16 equipment objects,28 architectural elements and zero
omitted equipment. Two malformed recipe cases are rejected. No Canvas, texture
rasterization, GLB generation, native UI, browser or model was run for041.

This candidate establishes no game-engine runtime, pressure simulation, VR support
