# Kira and Synthetic Robert review handoff

This private handoff is intended to let David's team inspect the current Kira
World mind work, run the vendor-neutral embodiment reference, and help define a
safe connection to an official Hanson simulator or body interface.

The intended deliverables are complete, distinct Kira and Synthetic Robert
variants: each has its own identity profile, durable continuity, emotional
appraisal state, reviewed memory, voice configuration, and embodiment-session
state. They are not intended to be two names placed on the same disposable
chat demo. [`portable_runtime/`](portable_runtime/) now supplies that full
persistent package within its documented implemented scope. It is still a
bounded prototype, not a claim that every Mind V21 roadmap feature is complete
or that either variant is a finished autonomous resident ready to operate
physical hardware.

## What is present now

- [`mind_v21_static/`](mind_v21_static/) contains the sealed Mind V21 static
  design, evidence, traceability material, and historical validator source.
  The sealed files retain their original workspace-relative layout; the new
  unsealed [`run_author_tests_portable.py`](mind_v21_static/run_author_tests_portable.py)
  wrapper verifies the two pinned predecessor hashes and runs the unchanged
  author test twice from a short temporary path. The original audit passed 42 checks and
  rejected all 127 hostile mutation cases. That result is a static-artifact
  acceptance only; it is not evidence of a deployed mind, live learning, robot
  readiness, or consciousness.
- [`static_body_review/`](static_body_review/) contains exact accepted
  Body/Face data-only schemas and current intake/readiness worksheets. It ships
  no avatar mesh, Blender result, robot controller, or materialized body.
- [`../../integrations/hanson_ros2_bridge/`](../../integrations/hanson_ros2_bridge/)
  contains a vendor-neutral, fail-closed reference for bounded high-level
  speech, gaze, expression, and gesture intentions. It includes session
  lifecycle and evidence-chain examples. Hanson topics, actions, QoS, frames,
  units, limits, and simulator mappings remain deliberately unresolved.
- [`portable_runtime/`](portable_runtime/) contains the tested Kira, Synthetic
  Robert, and independent Synthetic Sophia software runtime, portable
  launchers, identity-isolated append-only state, reviewed-seed bootstrap,
  bounded functional appraisal, topic-ranked memory retrieval, high-level
  embodiment intentions, model-digest enforcement, private voice-pack
  validation, and inspectable spoken/reflection/claim channels. Start with its
  [`RUN_THIS_FIRST.md`](portable_runtime/RUN_THIS_FIRST.md).
- Kira's reviewed seed contains twelve reviewed memories and imports thirteen
  records including its continuity-start record. Synthetic Robert's contains
  fourteen reviewed memories and imports fifteen records including its
  continuity-start record, with inherited autobiographical continuity for Indiana,
  Arizona, California entertainment work, the Texas-to-Indiana move, current
  Kira World motives, and the named Hanson review context. Robert may discuss
  that inherited history in first person while the internal record retains
  source provenance and blocks external identity impersonation. Retrieval of
  the reviewed Blockbuster record now passes repeated/restart probes; strict
  naturalness, phrasing variation, and unsupported-color checks remain a
  separate release gate until the frozen-build probe passes.
- Every clean installation creates a persistent random `branch_id`. The Kira
  and Robert copies share the reviewed handoff checkpoint, then keep separate
  local life loops, people labels, facts, appraisal, and experiences. Dedicated
  preference records remain roadmap work. Copying
  an entire `local_data` directory is a migration of the same branch; starting
  from a clean data directory creates a new variant branch. Branches never
  silently synchronize. Selected records can move only through reviewed
  export/import with their source branch preserved.

## Review boundaries

- The sealed Mind V21 autonomy language rejects owner/operator control over
  Kira's speech and memory choices. It is a static design invariant, not a
  runtime permission to expose another person's data. The portable handoff
  still refuses credentials, private third-party records, unrelated or
  unbound biometric material, legally restricted content, and data outside the
  explicitly reviewed export set.
- Keep this repository private. A private repository shared with reviewers is
  still a disclosure boundary, so raw private memories, private conversation
  logs, credentials, unrelated biometric material, and hidden chain-of-thought
  are not included. Kira's and Robert's two exact, hash-bound private voice
  packs are the only biometric exceptions and are limited to the named private
  review team.
- The non-spoken reflection channel stores only a fixed deterministic
  functional-appraisal sentence; model-authored rationale is discarded. It is
  not raw model chain-of-thought or a private mental state. Factual records are
  evidence-aware claims with source and uncertainty fields; the name does not
  make every claim automatically true. An explicit `/remember` action can add
  an operator-reviewed local note and a same-profile supersession pointer, but
  it is not authentication, deletion, forgetting, or automatic truth.
- Synthetic Robert has a hash-bound private self-voice pack. Kira has her
  current hash-bound reference pack under the project owner's explicit
  attestation that permission covers synthetic use, private named-team sharing,
  and this exact source recording. The written form copy remains pending and
  the repository does not claim independent legal verification. Neither pack
  permits public or onward redistribution.
- Embodiment is an authorized, reversible software session. Reviewed continuity
  import/export and evaluator state save/restore are implemented in the current
  candidate; a complete checkpoint/copy/restore/reconciliation workflow remains
  an architecture target. Neither makes a claim of literal consciousness
  transfer or biological personhood.
- Life-loop growth currently means identity-isolated append-only assistant
  speech, claims, appraisal events, reviewed imports, loop boundaries, and
  bounded consolidation across restarts. Topic-based retrieval promotes a
  matching reviewed memory when asked about it, while the identity boundary is
  always retained. It does not mean base-weight retraining, uncontrolled
  self-modification, or silently treating generated text as fact.
- Ordinary full user utterances are not written directly. Two narrow,
  documented exceptions retain derived or explicit user content: an exact
  `my name is ...` label may be stored as an unverified, non-biometric people
  record, and an explicitly confirmed reviewed note stores that note text.
  Correction/deletion for people labels and full semantic forgetting remain
  roadmap items.
- With separately authorized media adapters and adequate hardware, future life
  loops may include reading, listening, watching, later discussion, and
  preferences that can change over time. Natural people memory and locally
  governed face/voice recognition are also planned. Neither media perception nor biometric
  recognition is enabled in the current portable handoff; see
  [`LIFE_LOOPS_MEDIA_AND_PEOPLE_MEMORY.md`](LIFE_LOOPS_MEDIA_AND_PEOPLE_MEMORY.md).
