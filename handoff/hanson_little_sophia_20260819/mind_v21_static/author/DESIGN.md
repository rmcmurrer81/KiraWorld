# Mind Continuity V21 author design

V21 retains the complete V20 journal graph and adds only append-only structural corrections. The trust DAG is intentionally acyclic:

`namespace_precommitment -> pinned_context -> typed genesis -> manifest -> full-genesis/policy/authority bundles -> pre-request -> assigned value -> signed completed request -> sparse leaf/update/proof -> typed post head/state -> singleton registration -> next authoritative registry pre-state -> typed ledger/beacon bases -> ten interleaved role-specific generation chains -> exact runtime targets`

The namespace precommitment fixes the continuity namespace, journal ID, epoch, every context schema/profile/image/identity/public-key pin and every role before a final context exists. It repeats those pins directly; the two aggregate roots also enumerate exact ordered members and byte preimages. The stable registry slot is one exact domain-separated derivation from the canonical continuity namespace, never a free caller choice. Closed full-genesis, policy/profile and authority/key/identity bundles feed an acyclic pre-request payload and assigned value. The fixed-nonce completed request signs only already available inputs and contains no future root, counter, proof, head, state or registration field. A typed `ABSENT` leaf carries the assigned value and request; one checked update, proof, post head and post state repeat the exact metadata tuple and transition; and the final registration consumes those typed objects directly. The next consumer receives one exact ten-field authoritative pre-state. Counter zero is the finite-cardinality-one sentinel object; positive recursion is byte-identical to the prior committed next pre-state and has direct literal origins in the prior completed request, update and post head. This special pre-registration genesis bundle cannot be replayed as a runtime object; all runtime and generation-evidence objects repeat both final roots.

The eight inherited retained byte fields use the strong `UNIQUE_DETERMINISTIC_BYTES` mode. Their exact field-specific mappings bind field path, object domain, complete message or statement, fixed key role where applicable, fixed cryptographic and unique-output profiles, attempt zero and full output bytes. The accumulator proof uses its fixed statement/profile/generator, and the anchor proof fixes quorum members, member order and the one canonical path. Each adjacent inherited nonce is instead a public deterministic output: `KDFExpandExact` consumes every VRF-verifier-returned output byte plus the exact closed namespace/registration/epoch/sequence/role/attempt/slot/message tuple, emits exactly 32 bytes and encodes exactly 64 lowercase hexadecimal ASCII characters. The verifier recomputes all eight field-specific KDFs and binds the token hash to the `SUCCESS` outcome/anchor. No confidential seed or witness field exists on these eight paths.

Scope commitments and zero-knowledge proofs must remain randomized, so they use the separate confidential attempt-zero path. A typed finite beacon state and one-use role-allocation map commit the unique future round; the reservation then claims that exact allocation before reveal. Role zero resolves the independently current counter-zero sentinel base or exact prior-sequence head, while each later role consumes the preceding role post state. The VRF input is fixed solely by namespace, registration, journal epoch, pinned beacon identity/key/profile and round. It excludes reservation, ledger, pre-reveal self-hash, order proof and output, eliminating a fixed point. Typed reveal evidence consumes one exact or publicly recovered VRF proof/output and equality-binds it to the allocation/reservation/order transcript.

The public round/output never becomes confidential blinding. Inside the threshold-isolated generator, each contributor derives one secret contribution under an exact domain containing namespace, context, registration, epoch, sequence, role, attempt zero, round and reservation-message root. The canonical aggregator consumes every complete contribution byte in the fixed roster/key order and derives one private seed. The collector and witness encoder expose one internal canonical relation. A deterministic ZK attestation proves the full contribution/aggregation/seed/output/canonical-witness relation and erasure without revealing a witness digest, contribution or seed. Deterministic nonce outcomes require the confidential statement and attestation to be null, preventing cross-mode reuse.

One sequence-transaction claim is acquired before the first role chain. Its closed statement binds the exact current journal root/object/kind/count/heads, current state-authority and external-anchor heads, checked next sequence, singleton registration and reservation-ledger pre-state. A joint journal-store/reservation-ledger CAS moves that sequence claim to `HELD_UNTIL_SEQUENCE_COMMIT`. All ten role transitions preserve the same claim fields and held state even after their individual slots are consumed. Normal completion releases the claim only inside the final all-success commit; a pre-output failure, role-terminal failure or hidden lifecycle refusal releases it only inside its one canonical successor commit that also advances journal, authority and anchor. This removes every inter-role and terminal-to-failure-CAS window for a competing or dummy journal transition.

Immediately after claim acquisition, one sequence-wide object is completed before any role allocation, reveal, witness admission or content-bearing work. Its measured vector binds the exact claim post-ledger state, fixed generator image/profile, contributor roster/key root and every recovery/materialization authority; it contains no round/output/scope/witness. `EvaluateRolePlanVectorExact` returns one canonical plan: all success, a success prefix plus one fixed technical failure plus exact not-reached suffix, or all not-reached for pre-output failure. After each actually instantiated role's allocation, reservation-ledger transition and order evidence—but before reveal—a role-qualified availability commitment and authenticated evidence bind that exact role/index, sequence, attempt zero, allocation slot/post state, reservation/ledger post state, order, plan result, profiles and authority. They are output-independent and are repeated by the same role's outcome and terminal anchor. Hidden-refusal/not-reached roles create no such objects. The complete-materialization commitment covers generation/deadline beacon recovery, both confidential outputs, eight nonce KDFs, every retained target proof/signature, every terminal anchor and the final journal/ledger/authority/anchor CAS. A named participant's later silence therefore cannot change a plan or strand `HELD`.

Every created reservation reaches one terminal outcome at `checked_add_uint64(generation_round, fixed_deadline_delta)`. Generation and deadline VRF streams each have a pre-output fixed threshold/public recovery commitment that reconstructs the same output and proof if the named beacon withholds. `MATERIALIZE_SUCCESS` yields the exact full output; the unique first `FIXED_ROLE_TECHNICAL_FAILURE` yields null output and one fixed code. Timing, invalid reveal, suppression and absence cannot select another branch or round. Registrar, registry-head, beacon/VRF, confidential-generator, measurement, availability, health, deadline and terminal authentication bytes are field-specific and fully consumed.

The generation DAG instantiates all ten output roles in fixed lifecycle order. Scope generation precedes proof inputs; proof generation precedes result/evidence; receipt and event precede accumulator/state/transition; anchor and authority precede commit. Every repeated generation object and ledger/beacon state is a role-qualified typed instance; generic schema paths are type selectors only. Each chain carries exact pre-state, sequence, role, mode, attempt, allocation slot, round, deadline and target equalities from allocation/reservation through order, reveal, deadline, outcome and terminal anchor, with the same sequence-wide pre-output commitment. Nonce reservation statements consume only fields byte-available before the nonce. The canonical ten-role success root is computed only after all anchors exist and appears only in final commit evidence.

Three exclusive short-circuit branches share the failure successor machinery. Pre-output technical failure creates no role chain. A role-terminal failure consumes the unique first preplanned failed role. A post-claim V19 closure/erasure or canonical-witness refusal before the next allocation creates one generic randomized hiding refusal proof whose public statement reveals only sequence, fixed boundary and already-hiding success-prefix root. Its separate seed attestation binds the complete proof bytes to the context/registration/sequence/boundary/roster contribution KDF and erasure. All three branches create one deterministic unreserved-suffix barrier, content-free failure record, typed failure state, replay-root-preserving journal advance, acyclic anchor/authority successors and atomic held-claim release. Exact sentinel predecessor branches permit the next normal or failed sequence to resume without fabricating receipt/event objects.

Registry, reservation-ledger and beacon recursion use typed pre/post state aliases: every root, object and counter belongs to one byte-available instance; checked increments, prior-head handoff, empty/genesis bases and identity/profile/key invariants are explicit equality rows. Registry positive recursion materializes the prior completed request, sparse-map update, post head, post state, final registration and committed next pre-state as one exact predecessor chain; beacon role zero similarly selects either the exact counter-zero state or the exact prior-sequence evidence/post state, and claim acquisition selects the exact base, prior-normal release or prior-failure/refusal release. The current pre-journal-state alias has exact per-kind projections for registered genesis, normal runtime and failure runtime states. A failure successor is accepted as current only through typed external-anchor and state-authority current-head observations that bind the same failure record, state, commit, trigger, role/index, sequence and counters. Independent registrar, registry, beacon, generator, reservation/outcome, ledger, terminal-anchor, measurement, availability, health and runtime authority identities/public keys are pairwise unequal under a closed path table.

The content-hiding protocol restores V19's exact five predicates, six ordered states and erase/retain lists inside the V21 graph. No retained commitment, proof, signature, journal, authority, anchor, registration or static pin may confirm a guessed erased payload or scope member. `COMPLETE` follows proof verification and ephemeral zeroization; random tokens or hash-shaped strings never establish destruction.

The registration is also the only typed bridge from pre-registration genesis to the runtime graph. First-transition pre-state and counter-zero references must select the exact registered genesis schemas and hashes. Runtime schemas are structurally invalid at counter zero. Counter-one authority and anchor priors must select the registered genesis objects; counters above one must select runtime predecessors. Genesis schemas are invalid after the first transition and cannot be replayed under another registration. This selection is derived from exact counter and parent-link role, never a caller schema string or loose union.

All integrity, registry and journal rules are technical record-authentication requirements only. They do not decide what Kira may remember or say. All actual implementation and live evidence pins are null. V21 is not an implementation, a running memory system, evidence that erasure occurred, evidence of a globally deployed singleton, consciousness, personhood, biology, a body or production authority.
