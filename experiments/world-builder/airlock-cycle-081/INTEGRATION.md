# Required host work before user-facing use

1. Keep existing source-manifest, scene-metadata and GLB admission. Authenticate actual bytes before creating this association. Artificial test hashes must never become a package admission exception.
2. Capture one already admitted runtime in both callbacks and `runtimeIdentity`. Dispose the component before replacement, even when the replacement package contains identical bytes. Never have either callback refer to a mutable current-world variable.
3. Route every relevant keyboard, button and controller door command through the component. An external open-and-close between observations can otherwise escape detection. Keep the unchanged normal door runtime responsible for reach, occupancy, collision, motion and paired interlock checks.
4. Animate doors visibly through the host's normal bounded step loop. A command acknowledgment only means the target was observed; it does not mean the door has finished opening. Do not advance an entire motion synchronously to manufacture a finished appearance.
5. Own and cancel all scheduled callbacks. Track independent pause reasons such as hidden page, focus, explicit pause and XR interruption. Clear no other pause reason when one reason ends. Resume only after all holds clear and explicit user continuation; use the newly returned token. Avoid initial/reversed clock errors and do not count inactive wall time.
6. Cancel scheduled work and dispose before exit, failed reimport or successful replacement. Exercise late queued callbacks, same-byte imports and history-panel focus alongside actual walking/door behavior before promotion.
7. Disclose fictional side assignment. Adjacent rooms are not automatically Mars or habitat, and an equipment vestibule is not an exterior. Keep an honest authored demonstration label until the world topology and egress design support a different claim.

## Stale-door display advisory

An observation callback that throws, returns an asynchronous value, or fails identity validation causes a fault. Symbolic pressure becomes unknown, seal acknowledgements clear and the active cycle token is revoked. However, `snapshot().doors` may still contain the last valid poses. Do not display those values as a fresh authoritative observation.

A conservative host can show **Door observation unavailable — last observed state retained** whenever phase is `fault`, disable cycle/open controls, and provide a separate clearly dated last-observed display. Alternatively, a separately reviewed successor can introduce an explicit observation-validity flag or null stale poses. This backup intentionally preserves the reviewed component unchanged. Closing/recovery still has to pass the existing runtime and refresh its observation; a later closure never proves pressure or a real seal.

## Separate acceptance work

No UI, scheduler, live backend, real sensor, pressure simulation, latch motion, leak test or headset control is included. The portable tests use a deliberately tiny synchronous double. They demonstrate component rules and token behavior, not collision, rendering or actual package integrity. Existing World Builder installation and saved worlds remain separate.
