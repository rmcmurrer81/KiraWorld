# Experimental World consumer083: fictional airlock exercise

This additive source snapshot integrates the reviewed symbolic airlock component with the existing desktop package consumer. A compact contextual panel distinguishes geometric closed/stopped doors from explicitly acknowledged fictional seals. A six-second active-time cycle selects one paired side before opening is permitted. The Equipment Vestibule is an interior room, not the surface of Mars. This is an authored interaction exercise, without pressure, pump, seal, latch or life-support physics.

Both the keyboard door action and the nearby-door button use the same captured package runtime. Existing reach, collision, occupied-swing and paired-door interlock checks remain. The083 host rejects unbound IDs and stale/disposed sessions before runtime dispatch, and cannot authorize continuation while the symbolic component is faulted. The host does not repair an externally bypassed door or reset faults automatically.

Pause reasons aggregate. Hidden pages, loss of focus, room exit, package replacement and disposal invalidate scheduled callbacks. Returning requires an explicit resume; time spent away does not finish the cycle. The first animation frame establishes its own baseline, active steps are bounded, and invalid or reversed time pauses. Seal acknowledgement is revoked when that door moves; closing a door alone does not acknowledge a seal.

## Included and excluded

`candidate/` is exact frozen083 source, including the unchanged package loader, walking/door runtime, greenhouse controls and written Mars-history library. The source and asset admission hashes are unchanged. **Private world packages, GLBs, textures and saved owner data are excluded.** This backup therefore does not contain an importable world. Arbitrary packages are not accepted by loosening the loader. The fixture used by the portable tests is clearly artificial and bypasses no production admission gate.

The vendored Three.js subset and its MIT license are byte-identical to the already reviewed and published080 snapshot. No new third-party runtime was downloaded. Original project licensing is unchanged.

The six history chapters remain written transcripts with their existing dated source links; this revision changes no historical facts. Every narration entry is absent. Greenhouse readings remain illustrative session-local data. Mounted exported screen textures remain saved snapshots; the explicit dynamic airlock UI observes current local doors. This is not live telemetry, voice narration, completed headset support or an installed World Builder upgrade.

## Evidence and limits

Independent source review verified the narrow083 correction and preservation of its082 parent. The local integration suite passed19 affected cases using actual admitted package/runtime code with inert display adapters. Separately, the public portable suite passed25 checks using invented metadata and a synchronous double; it does not prove geometry, package import, navigation or collision.

A separate native desktop walkthrough imported the preserved package and approached the hatch with visible steps. It observed the initial unknown-side hold, both fictional seal acknowledgements, completion of the vestibule cycle, occupied-swing refusal, opening after stepping clear, and refusal to begin another cycle while open. Closing revoked the seal. Re-acknowledgement allowed the opposite-side cycle. Clicking Pause caused focus-based suspension; explicit Resume completed the cycle, after which opening against the opposite side was refused. The manual-pause handler was not separately isolated from the focus handler in that walkthrough.

These checks are technical evidence, not owner art acceptance, real seal/pressure validation, narration approval or a headset comfort test. Native inspection ended and its local server was closed. Existing installed World056 and saved worlds remain unchanged.

The source backup is additive: prior experiments and unrelated repository files are preserved. `TESTS.md`, `SOURCE-INVENTORY.json` and `REVIEW-SUMMARY.json` describe the exact scope without including private machine receipts.
