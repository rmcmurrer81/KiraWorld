1. Know the workspace

The Editor workspace combines the live storyboard, video/thumbnail preview, decisions, and Editor Chat.

Project & controls

Choose the subject, format, length, research strictness, outputs, voice, captions, and source-video policy.

Editor workspace

Review each proposed clip, image, title card, audio decision, thumbnail, and concept slot.

Workflow

Run research, fact sheet, script, visual planning, narration, owner review, corrections, and packaging.

Review & corrections

Approve, Reject, Replace, Edit, or Lock an item. A rejected item cannot enter the deliverable.

Staging rule: an owner-review render is a draft for watching. It is not an approval, a clean final, or permission to publish.

2. Start a project

  1. Select New private project.
  2. Enter a precise subject. A useful subject names the work and its scope, such as “Detroit: Become Human — story, android treatment, and branching outcomes.”
  3. Choose the video type. The type controls the chapter structure and visual expectations.
  4. Choose the desired length and chapter count. Length is an editorial target, never permission to pad or repeat.
  5. Enter required talking points, subjects to include, subjects to avoid, and your notes.
  6. Enable captions and the required landscape, vertical, or square outputs.
  7. Enable trailer/video use only when relevant footage can be sourced and reviewed. Choose whether source audio is heard, ducked, or muted for each clip.
  8. Save. The project gets its own folder, records, assets, review decisions, and audit history.

Project controls. The current styled build uses the same workflow with a darker editorial interface.

4. Research, script, and source planning

  1. Run research from inside Video Studio so the project records every query, candidate, selected source, and rejection.
  2. Prefer first-party sources: official publishers, studios, networks, developers, press kits, manuals, and credited releases.
  3. Review the fact sheet. Correct disputed dates, versions, identity knowledge, and timeline boundaries before narration.
  4. Read the complete script aloud. Remove repetition, production language, broken thoughts, and corrections that refer to rejected drafts.
  5. Review the pronunciation dictionary. Generate a short proof for names that have been mispronounced.
  6. Inspect the shot list. Every item needs its source, exact in/out point, audio mode, purpose, continuity/subject ID, and rights note.

Good test: if the narration changes from one movie, game chapter, character, or continuity to another, the storyboard should show a deliberate visual change at the same moment.

5. Review visuals and concepts

  1. Select a storyboard row and inspect it at full size and at small preview size.
  2. Approve a correct candidate, Reject a wrong one, Replace its source, Edit its timing/text/crop, or Lock a choice you do not want automation to change.
  3. Use Editor Chat for specific corrections, such as “Replace this clip with Connor questioning the deviant; keep narration unchanged.”
  4. For generated concepts, approve the prompt and storyboard slot first. The Studio records provider, prompt, date, purpose, and hash.
  5. Concepts must permanently read CONCEPT — NOT CURRENT FUNCTIONALITY. Rejected concepts are excluded automatically.

A concept image is not a substitute for available runtime evidence, gameplay, a screenshot, or an approved source image.

6. Narration, clips, and audio

Muted

Robert’s narration is the only intended audio. Use for most explanatory footage.

Ducked

Source ambience remains low beneath narration. Robert’s voice must remain clearly dominant.

Heard

A deliberate source excerpt is featured. Use a precise in/out and return cleanly to narration.

Never accidental

No unintended silence, clipped narration, corrupted AAC, mismatched stream duration, or wrong-version visuals.

Before rendering

  • Listen to pronunciation proofs.
  • Confirm every narration WAV exists and belongs to the correct chapter.
  • Ensure each visual plan lasts at least as long as its planned narration.
  • If a good clip is shorter, follow it with another matched clip or sourced still; never cut the sentence.

7. Render and complete owner review

Clean-export rule: Owner-review is an internal project status. Video Studio never burns draft or review labels into the exported video. The one exported MP4 remains visually clean while its project metadata continues to say that Robert’s review and rights review are pending.

  1. Create the owner-review MP4. The Studio decodes video and audio through EOF and compares their true durations.
  2. Generate captions and chapter times from the completed timeline, not from an earlier estimate.
  3. Watch the complete MP4. Check story order, visual changes, narration, source audio, repeated footage, captions, and ending.
  4. Record corrections against exact storyboard items. Re-render only what needs changing when accepted media and narration can be reused.
  5. Review thumbnails at full resolution, normal YouTube size, and phone size. Keep aspect ratio and faces undistorted.
  6. Review one clean YouTube set and one clean Facebook set. No upload occurs.

Status language: use AWAITING_ROBERT_OWNER_REVIEW until Robert accepts the watched package. Machine checks do not make a video approved.

8. FAQ

Does Video Studio upload automatically?

No. Uploading and publishing are disabled.

Can I change one bad clip without rebuilding accepted narration?

Yes. Reject or replace the storyboard item and preserve accepted files. Hash records show which files were reused unchanged.

What if a trailer is shorter than the narration?

Add another correctly matched shot, then a sourced still or labeled comparison graphic. The Studio must not truncate narration or loop unrelated footage.

Why is a project blocked after a video file exists?

A file is not enough. Stream decoding, audio/video duration, silence, narration coverage, captions, source alignment, rights notes, and review state can still fail.

Can generated art be used?

Only through the Studio’s disclosed concept workflow after prompt approval. It remains labeled as a concept and cannot pose as current functionality or evidence.

What does Lock do?

It preserves an accepted choice from later automatic replacement. Lock does not grant publication rights.
