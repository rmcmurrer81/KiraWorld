# Validated body and mind result template routing - current boundary

Date: 2026-08-11

Status: `CURRENT_OWNER_POLICY_DEFAULT_OFF_UNTIL_EACH_RECEIVER_INTEGRATION_PASSES`

This document records the owner's direction that body-development results
must improve the Avatar Builder and mind/person-development results must
improve the Temporary Creator's template for new synthetic people, variants,
and experts. It applies to results involving Kira, Lisa, Synthetic Robert,
every other resident, every variant or expert, and any future person.

This is a routing policy, not evidence that a result has already been installed
or that a person, body, memory, emotion, relationship, or production route has
changed.

## Shared acceptance rule

A result is eligible for a positive reusable template only when all of the
following are true:

1. its exact source/evidence bytes and SHA-256 identities are recorded;
2. the author tests passed;
3. a different independent review explicitly accepted the exact result for
   the claimed static or live scope;
4. the result is generalized and contains no person-specific private payload;
5. the receiving Avatar Builder or Temporary Creator integration has its own
   exact contract, tests, append-only evidence, and independent acceptance;
6. the receiver remains default-off until that receiving acceptance.

Author success, an attractive render, a passing static test, a plausible model
answer, or a controller result alone is not enough.

Rejected, failed, consumed, partial, and unreviewed results remain valuable,
but only as negative tests, failure classifications, and do-not-repeat lessons.
They must never be selectable methods or installed capabilities.

intersection and deformation tests, rig/weight-transfer methods, anatomy

It must not receive or expose private reference images, identity measurements,
person-specific vertices/faces, private anatomy observations, person-specific
morphs, or an unaccepted Kira body renamed as a generic method.

accepted R25 external/internal body, anatomy, physiology, movement, Blender

  out-of-bounds-read rejection;

  annotation hypothesis;

These lessons may enter only an append-only Avatar Builder intake/negative-test
layer. They do not create a selectable reusable method. Any future accepted
body method must pass the existing reusable-method promotion gate and an exact
generalization review before `selectable_methods` can change.

## Per-result routing record

Every later routed result must record:

- `result_id`, lane (`body` or `mind`), exact claimed scope, and source date;
- source/evidence/audit paths, byte counts, and SHA-256 values;
- independent decision and reviewer identity;
- `positive_template_candidate` or `negative_test_only` disposition;
- a redaction/private-data review;
- exact receiving template/method version;
- receiver test, seal, review, and promotion status;
- explicit statements that static acceptance is not lived state and that no
  person is modified merely by routing the lesson.

No implicit inheritance or bulk copying is allowed. Each accepted lesson is
append-only, independently traceable, reversible at the receiver pointer, and
revocable from future creation templates without rewriting existing persons.
