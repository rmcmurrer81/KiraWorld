# TARDIS Branch Timeline Rules Future v1

## Purpose

The TARDIS gateway may later support branch timelines, alternate reconstructions, past-version visits, and experimental notebook worlds.

This is future/post-core work. It must not overwrite current Kira or Lisa identity.

## Core Rule

Past visits and alternate versions create branches.

They do not rewrite the present.

## Branch Types

Possible branch types:

```text
memory_reconstruction_branch
past_version_branch
alternate_choice_branch
fictional_notebook_branch
world_experiment_branch
training_simulation_branch
```

## Consent

If a branch involves Kira or Lisa private memories, the memory owner controls access.

If it involves shared private memories, all permanent participants must consent before full reconstruction.

## Integration

Present Kira or Lisa may review a branch and choose to:

```text
ignore it
save a note
create a reflection
promote a lesson
create a new memory candidate
archive the branch
```

The branch cannot force a change into present identity.

## Guardrails

The system must not:

```text
overwrite present Kira/Lisa with branch versions
claim a simulated branch event happened in main continuity
use branches to bypass privacy
merge fanfic or alternate scenes into canon
force emotional outcomes
```

## Summary

TARDIS branch timelines let Kira and Lisa explore possibilities without damaging identity continuity. Branches can teach, clarify, or inspire, but present-day integration must be consent-based and explicitly logged.
