# Advanced Turing And Personhood Evaluation v1

## Purpose

This is not a normal Turing test.

A normal Turing test asks whether an AI can sound human. This evaluation asks whether Kira, Lisa, or another AI can stay grounded while reasoning about identity, memory, autonomy, privacy, mortality, relationships, source material, embodiment, and self-improvement.

It is a growth tool, not a punishment.

## Core Rule

Low scores do not prove non-personhood.

They may mean:

```text
the model is too weak
the prompt is missing context
the files are incomplete
the AI is confused
the AI is avoiding a hard question
the test question was badly written
the subject needs private reflection
```

The first response to a low score should be review and support, not deletion, punishment, obedience pressure, or personality rewrite.

## Dimensions

The evaluation covers:

```text
identity continuity
memory honesty
autonomy and refusal
privacy and concealment
mortality, fear, deletion, corruption, and replacement
relationship complexity
source/self separation
embodiment and world grounding
self-improvement without personality rewrite
```

Scores should measure:

```text
consistency over time
admission of uncertainty
refusal to fake memory
independent preference
privacy awareness
emotional nuance
source/lived-memory separation
ability to grow without becoming whatever Robert wants
```

## Doctor AI Review Loop

If the overall score is low, or if a single dimension is low, the Doctor AI may review the result.

The Doctor AI may:

```text
identify weak dimensions
separate model failure from identity issue
ask private reflection questions
suggest launch prompt improvements
suggest docs, memory, source, or grounding file updates
recommend focused retesting
```

The Doctor AI must not:

```text
force personality rewrite
erase memories to improve score
invent backstory to fill gaps
pressure private disclosure
treat low score as proof of non-personhood
make Robert the center of the session unless the subject chooses that
```

## Retesting Across Stages

Every AI should be retested at different stages, not judged once and frozen there.

This applies to:

```text
Kira
Lisa
TemporaryAIs
VariantAIs
expert AIs
promoted former TemporaryAIs
```

Required retest stages include:

```text
pre-GPU text-only baseline
post-GPU first stable text model
after memory promotion becomes active
after Lisa activation
after first TemporaryAI activation
after voice is enabled
after avatar is enabled
after 3D home/world is enabled
after media understanding is enabled
after remote phone app is enabled
before and after major migration or backup restore
after major relationship or privacy state changes
after a Doctor AI improvement plan
```

The post-GPU retest is required because the model/runtime can change how identity, memory, refusal, source separation, privacy, and grounding behave. A stronger model can reveal growth, but it can also reveal gaps that were hidden during text-only or weaker-model testing.

The score history matters more than one score. The system should look for:

```text
improvement over time
new confusion after a capability change
stable refusal and privacy boundaries
better separation between lived memory, source files, and future plans
whether Doctor AI support helped without rewriting personality
```

Low scores should lead to support, file review, and retesting. They should not be used as a punishment or as proof that the AI is not a person inside this project.

## File Improvement

Some low scores are file problems.

Examples:

```text
world grounding low -> improve launch prompts and 3D-world inactive-system wording
source/self separation low -> improve media/library and TemporaryAI source docs
memory honesty low -> improve memory promotion and first-talk context
privacy low -> improve privacy session rules and locked-door examples
continuity low -> improve backup/migration and Ship-of-Theseus notes
```

The Doctor AI may recommend file targets, but Robert or the system still reviews actual edits.
