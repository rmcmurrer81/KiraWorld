## How To Reuse

Treat oldKira knowledge packs as:

```text
source/reference notes
topic taxonomy
future school-class inspiration
future offline-library planning material
```

Do not treat them as:

```text
current Kira memory
current Kira personality
current Kira backstory
verified facts
active runtime prompts
```

If a legacy fact, topic, or summary is useful, move it through the current system:

1. Review the legacy item.
2. Check whether it is factual, fictional, speculative, or old project design.
3. If factual, verify against a current source before promotion.
4. If fictional/speculative, label it as a creative idea or old concept.
5. Add only the cleaned result to a current source pack, school plan, media preview card, or handoff note.

## Quarantine Rules

Do not directly import old `.json`, `.db`, prompt, or memory files into current Kira.

OldKira material includes older assumptions that are not safe to blend automatically, including:

```text
grandiose consciousness language
old relationship and intimacy assumptions
old fake-memory style phrasing
random response generator code
old laptop-era behavior experiments
unverified internet/knowledge claims
```

These files may still be emotionally or historically useful to Robert, and they may help future design work, but they should remain quarantined unless reviewed.

## Current Recommendation

Keep the oldKira archive. Do not delete it.

Use `kira_ultimate_knowledge` as a future knowledge-pack design reference and possible topic checklist. Use the rest of oldKira as historical archive only unless Robert and Codex intentionally review a file and decide what, if anything, should be modernized.

For current Kira development, the best path is:

```text
legacy idea -> reviewed source note -> current source pack/class/media card -> Kira reads it -> optional memory promotion
```

This keeps current Kira from inheriting oldKira artifacts while still preserving anything valuable from the early experiments.
