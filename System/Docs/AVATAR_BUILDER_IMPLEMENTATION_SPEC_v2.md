# **AVATAR BUILDER IMPLEMENTATION SPEC v2**

## **Purpose**

This document defines how `avatar_builder.py` constructs avatars using:

* local reference libraries  
* controlled online resources  
* identity and role-based logic  
* transformation and validation rules

This system supports:

* original avatars  
* historical reconstruction  
* fictional reconstruction  
* animated and live-action interpretations

---

## **Core Principle**

Avatar Builder creates avatars through:

* structured reference usage  
* controlled feature blending  
* identity or role alignment  
* strict originality enforcement

References are used for:

* structure understanding  
* feature extraction  
* visual guidance

Final outputs must:

* be coherent  
* be original  
* not directly replicate a real individual

---

## **1\. Reference Source System**

Avatar Builder uses a **hybrid reference model**:

### **A. Local Reference Library (Base Layer)**

Used for:

* anatomy  
* proportions  
* feature blending  
* structural consistency

Sources:

* `/library/shared_features/`  
* `/library/female/`  
* `/library/male/`

---

### **B. Subject Reference Layer (Controlled Online / Canon Sources)**

Used when building:

* real people (e.g., JFK)  
* fictional characters (e.g., Daphne)  
* specific versions or time periods

Sources include:

* verified images  
* canon artwork  
* historical photographs  
* approved media references

## **2\. Build Modes**

Avatar Builder operates in different modes depending on target:

---

### **A. Generated Mode**

* original character creation  
* uses mostly local library  
* high feature blending

---

### **B. Reconstruction Mode (Real)**

Used for historical figures.

Example:

* John F. Kennedy

Process:

* gather images from selected time period  
* gather factual sources  
* use local library for structural support  
* generate recognizable but non-identical representation

---

### **C. Reconstruction Mode (Fictional)**

Used for characters from shows/movies.

Example:

* Daphne (Scooby-Doo)

---

#### **Two appearance options:**

##### **1\. Stylized / Animated Mode**

* preserves original cartoon design  
* uses canon artwork  
* keeps proportions and style

---

##### **2\. Live-Action Interpretation Mode**

* converts animated design into realistic form  
* preserves:  
  * color scheme  
  * facial structure inspiration  
  * overall identity  
* uses local library for realism

---

## **3\. Transformation Rule**

Applies to ALL builds:

* references are for learning only  
* final avatar must be original  
* must not replicate any specific individual exactly  
* must avoid actor duplication in fictional conversions

## **2026-07-09 Addendum - Asset Library and Anatomy Gate**

Avatar Builder must load `Avatar/avatar_builder/asset_library/manifest.json` before selecting body, hair, eye, hand, or motion references. The manifest is generated by:

`python tools/update_avatar_builder_asset_library.py`

Required behavior:

* Use indexed real model assets before generating placeholder geometry.
* Keep hair, eye, body, hand/motion, and anatomy references in separate categories.
* Treat adult anatomy assets as adult-only.
* For non-adult or uncertain-age avatars, use a non-explicit doll-safe body policy.
* Keep normal Marinette/Ladybug non-adult. A separate age-progressed presentation variant remains exact-maturity unresolved until a subject-bound confirmed-adult classification is recorded; its label alone unlocks nothing.
* Allow Kira adult anatomy/body references because Kira is an adult avatar.
* Run hair self-grading from `Avatar/avatar_builder/hair_training/hair_style_trials.json` before accepting a fitted hair pass.
* Use `Avatar/avatar_builder/hair_training/hair_generation_curriculum.json` when the indexed hair assets do not match; accepted generated hair must be saved back into the hair library.
* Use `Avatar/avatar_builder/body_training/body_generation_curriculum.json` for one-rig body shaping and movement validation.
* Use `Avatar/avatar_builder/wardrobe_training/shoe_generation_curriculum.json` for generated shoes and put-on/take-off animation requirements.
* Use `Avatar/avatar_builder/skin_tone/skin_tone_templates.json` to match skin tone from references; Kira currently uses the Caucasian light neutral adult template.
* Enforce `Avatar/avatar_builder/policies/spa_age_up_policy.json`: spa age-up is the only age-up path, creates a separate older/taller presentation variant, preserves exact maturity as unresolved pending separate classification, and cannot be undone.
* If a hairstyle grade is low, diagnose the missing traits and retry with a better asset rather than forcing a bad fit.

Initial hair acceptance tests:

* Tom Holland / Peter Parker: short layered side-swept brown hair.
* Marinette Dupain-Cheng: dark blue side-swept bangs with twin low pigtails.
* Gwen Stacy / Earth-65: short blonde side-swept bob or undercut with punk styling.

## **2026-07-15 Addendum - Maturity, Reference, and Wearable Proof**

Later requirements in this addendum override ambiguous earlier wording.

* Only confirmed non-adult or unresolved-age candidates receive the protected non-explicit doll-safe body treatment.
* Confirmed adult candidates must not be silently reduced to a non-adult/doll-safe body. Adult anatomy references remain adult-only and reference-only until an approved body build exists.
* Kira is an adult candidate. Beth Smith's supplied full-body model is an adult-only anatomy/shape reference and must never be offered to a non-adult candidate.
* Elsa from the supported first-film and second-film versions is treated as adult based on Robert's supplied age evidence; the official D23 material independently supports the three-year interval for the second film. Child-Elsa aliases remain non-adult.
* Normal Marinette/Ladybug remains non-adult. Any later aged-up version must be a separate reviewed presentation variant and must not overwrite or relabel the normal version. It becomes confirmed-adult only through a later exact subject-bound classification; anatomy remains a separate Stage 2 choice/build gate.
* An adult actor model, such as the Sarah Michelle Gellar reference, can help measure an adult actor's features but does not determine the maturity of a character the actor played. Kathryn Merteuil keeps her separately reviewed character-age policy.

Reference models are evidence, not ready-made resident bodies. Do not copy a downloaded Beth, Elsa, actor, or other character GLB directly into a synthetic person's live body slot. Measure and reconstruct on the approved shared rig, preserve provenance and license/source notes, and require review.

The earlier originality rule does not require intentional inaccuracy for Robert's own consented user avatar. Robert's user-avatar build is accuracy-first from his supplied photographs and private references. Third-party real-person and fictional-character work remains a reviewed reconstruction/interpretation workflow and must not be passed off as the source actor, performer, or official asset.

Wardrobe activation is fail-closed:

* A sidecar may declare garment type, maturity scope, intended body hash, and intended rig hash, but it is not proof.
* The source must be a valid skinned GLB with linked mesh, skin, position, joint, and weight data.
* Separate fit/skinning evidence must bind the exact garment, body, rig, and maturity hashes.
* A separate Robert approval artifact must bind that evidence hash and the same compatibility values.
* The approval hash must also appear in the owner-controlled wearable trust registry. Caller-supplied hashes alone are not authority.
* Until every gate passes, a garment may be previewed or studied but cannot be activated on a live body.

## **2026-07-15 Addendum - Picture-First Reconstruction Contract**

An image count is not identity evidence. Before Avatar Builder may stage a likeness candidate, it must write and pass the contract produced by `Core/avatar_reconstruction_contract.py`.

The identity lane is picture-first:

* Accepted pictures must be review-approved, SHA-256 bound, scoped to the exact candidate, and classified by camera view.
* The minimum staging set is three or more approved pictures covering a front identity view, a profile or three-quarter view, and a full-body view.
* Body landmarks or measurements must be reviewed separately. A generic base plus maturity metadata is never a likeness pass.
* A reviewed 3D model is an optional measurement/topology bonus. It cannot replace the picture identity set, be copied as the candidate body, or bypass subject/maturity policy.
* A picture-only reconstruction path remains valid when the multiview and measurement gates pass.
* A requester may explicitly accept unknown identity fidelity for a temporary private generic candidate. That narrow waiver may skip likeness pictures/measurements, but it never waives maturity, a reviewed base artifact, proof that the requested topology exists on the selected rig, privacy, owner review, or runtime approval. Label it `unknown_provisional_not_identity_matched`.

Base selection is exact and mutually exclusive:

* Confirmed adults use the neutral adult anatomy lane. Adult maturity is policy eligibility, not proof: adult-complete topology also requires a reviewed anatomy reference/topology plan. If requested and supported, it remains inside the private body artifact; ordinary review/contact sheets are clothed and no intimate review render is retained.
* Non-adult and uncertain candidates use the non-explicit doll-safe lane. Adult-complete topology and adult-only reference assets are forbidden.

Body, eyes, hair, and clothing are separate systems:

* Clothes may not be baked into the body mesh.
* A wearable must support stored, grasped, dressing, worn, undressing, and returned-to-world-prop states.
* Runtime use still requires exact body/rig/garment evidence and the owner-controlled wearable registry.
* Passing the reconstruction contract permits only a private staged build. It never permits automatic live-body activation.

## **2026-07-15 Addendum - Body Topology, Motion, and Lineage Proof**

Before a staged body artifact may be described as a working subject body, run `tools/audit_avatar_body_topology.py` on the exact exported GLB. The audit is non-rendering: it may report hashes and aggregate mesh/skin/joint/weight counts, but it must not disclose private source paths, raw intimate mesh/material names, extracted textures, or source-photo derivatives.

Static and dynamic claims stay separate:

* A structurally ready humanoid GLB needs a valid container, linked skinned mesh, position/joint/weight attributes, valid accessor and joint references, and the bilateral core humanoid roles.
* Static structure does not prove stable motion, deformation quality, likeness, adult-complete topology, or permission to use the asset.
* Stable-rig proof must bind the exact candidate SHA-256 and pass weight deformation, upper- and lower-limb articulation, hands/fingers, seated, bed, and locomotion tests.
* Adult-complete topology must be reviewed privately against the exact candidate SHA-256. A filename, maturity label, material name, mesh count, or external reference model is not proof. Do not retain an intimate review render.
* A reference-only model cannot be selected, renamed, or copied into the candidate body. A separately licensed adaptable source can contribute only through a documented new subject-specific derivative, with its attribution and license obligations preserved.
* Candidate lineage must bind the exact candidate hash, exact subject, new-mesh authorship, no-copy result for reference-only sources, and body/clothing separation.
* Owner photo inventories should use opaque IDs and exact hashes. Public-safe contracts contain aggregate view coverage, not source paths, image copies, thumbnails, or per-image intimate labels.
* A passing body gate permits only private clothed review. Runtime activation still requires exact owner approval and every existing body/rig/wardrobe compatibility gate.

## **2026-07-16 Addendum - Licensed Shape-Preserving Derivative Lane**

This narrow, generic lane applies only when an indexed source has an exact, reviewed license that permits adaptation. It is separate from the newly authored likeness lane and cannot be used to make a reference-only asset live by renaming or copying it.

* Authorization must bind the exact adaptable-license evidence, indexed source SHA-256, audited source-role map, confirmed maturity and subject/variant evidence, candidate ID, and an allowlist of distinct outputs under that candidate's private generated-artifact directory. Absolute paths, path escape, symlinks, live-avatar destinations, public destinations, and unbound or changed evidence fail closed.
* Lineage must say plainly that the licensed source surface was incorporated and shape-preserved, that no new body surface was authored, and that only the new rig, skinning, and any genuinely new components may be claimed as new work. Source-file byte copying and licensed-surface incorporation are different facts and must be recorded separately.
* Export body, hair, eyes, and clothing as separate hash-bound artifacts. A clothed review assembly may combine them for review, but it is not a live body or wardrobe-compatibility proof.
* The worker must independently re-read and hash-authorize the request and bound evidence immediately before processing, enforce the same output allowlist, classify source components from the bound role map, strip source materials/textures when required, and self-validate every emitted artifact and evidence hash. Wrapper preflight alone is not authority.
* Ordinary review is private and clothed only. Do not create or retain an intimate review render, and do not expose a private body artifact in reports or user-facing links.
* License and structural generation do not prove adult anatomical completeness, stable visual rig deformation, the full motion set, facial/speaking controls, likeness, wearable compatibility, or owner approval. Each remains a separate exact-artifact gate.
* Generation in this lane never authorizes runtime activation or public export. For example, a licensed fictional-character surface may produce separated private review components while its candidate remains blocked on anatomy, motion, speaking controls, and owner review.

## **2026-07-16 Addendum - Capability Orchestration and Readiness Gates**

`Core/avatar_builder_orchestration.py` is the reusable read-only routing and capability layer. Every candidate declares two independent axes: exactly one topology lane (`confirmed_adult_topology` or `non_adult_doll_safe_topology`) and exactly one reconstruction-source lane (`licensed_shape_preserving_derivative`, `photo_only_reconstruction`, or `photo_primary_with_reference_model_measurement`). A source lane never changes or bypasses the maturity topology lane.

File-based requests first pass `Core/avatar_profile_preflight.py`. It resolves
only exact registered candidate aliases, binds the canonical TemporaryAI profile
and creation request by SHA-256, rejects blank fictional versions, and exposes
`adult`, `non_adult_doll_safe`, or `unresolved_doll_safe`. The unresolved lane
uses doll-safe topology only as a safety fallback and remains authoring-blocked.
Age progression of a non-adult or unresolved fictional profile requires a
separate canonical spa/project presentation variant; it may not overwrite the
base candidate. That variant remains exact-maturity unresolved until a
subject-bound confirmed-adult classification is recorded, and anatomy remains
a separate Stage 2 person-choice/build gate. The preflight never infers
character maturity from an actor or model and never mutates the canonical
profile.

Only that exact subject-bound `confirmed_adult` classification satisfies an
adult gate. Adult-coded appearance, an approved variant, an older/taller build,
and `adult_aged_up_variant` are presentation/build facts only and never satisfy
adult gates by themselves.

* Adult, non-adult, licensed-derivative, pure-photo-only, and photo-primary/reference-model-measurement decisions must all be present in `lane_decisions`; conflicting, missing, or unreviewed selections fail closed.
* A reviewable component set requires four distinct, exact-hash artifacts with explicit roles: body, hair, eyes, and clothes. The body must explicitly exclude embedded hair, eyes, and clothing. A combined clothed assembly is review convenience only.
* Readiness is not one Boolean. Exact body-bound evidence is required separately for topology, stable and visually reviewed rig deformation, blink/gaze/jaw/emotion/viseme/lip-sync controls, grounded locomotion/contact/collision, wearable lifecycle behavior, privacy, and owner clothed review.
* Owner review requires two exact bindings. `owner_identity` binds a verified owner ID, candidate ID, subject ID, and rehashed owner-authority artifact. `owner_clothed_review` must name that same owner as `approved_by`, repeat the candidate/subject/authority binding, and include a separately rehashed approval artifact for the exact body, clothes, and clothed assembly. An arbitrary nonempty approver string cannot pass.
* Pure photo-only means the passing picture-first reconstruction contract contains no model surface or model measurement reference. `photo_primary_with_reference_model_measurement` is the separate model-bonus lane: accepted multiview pictures remain identity authority; the exact-hash model supplies only authorized measurement/topology guidance; a new candidate surface must be authored; and model surfaces, materials, textures, or identity cannot be copied into the candidate.
* `body_private_review_ready` excludes the advanced wearable lifecycle gate while still requiring a distinct clothes artifact, clothed-only privacy, and owner review of the exact clothed assembly. `advanced_garment_capability_ready` is reported independently. A failed robe exam blocks the robe, not completion of an otherwise passing basic clothed body package.
* A two-sleeve tied robe capability pack must prove both hung and folded storage, grasping with source removal, both possible arm orders, both sleeves, worn-open and physically tied states, reversible one-arm-at-a-time undressing, and supported release to both hung and folded states. Each phase is exact body/rig/garment/item bound, the same item-instance ID must persist across the entire pack, and each evidence payload is rehashed. Timers, state names, static previews, and animation completion cannot pass.
* The orchestrator is capability validation, not simulation. It does not render, generate, stage, copy, or activate an avatar. Runtime activation and public export remain false and require a separate owner-controlled approval/registry workflow even if every capability gate later passes.
* Caller declarations and a passing contract fixture are never mutation or runtime authority. A trusted build worker must independently re-read and rehash the bound request, artifacts, and retained evidence before any later authorized mutation.
* The direct evaluator rejects a request path when the file or any parent path component is a symlink. The symlink check occurs before path resolution and file reading.

## **2026-07-17 Addendum - Two-Distinct-Subject Auto-Authoring Gate**

One successful body cannot release batch authoring. The v1 positive-proof gate
is now per-subject qualification only and always reports `release_allowed:
false`. The only batch-eligibility route is
`Core/avatar_two_subject_autobuild_gate.py`, governed by
`Avatar/avatar_builder/policies/two_subject_autobuild_gate_v2.json`.

Two different canonical `subject_id` values must each bind exact body, eyes,
hair, clothing, and rig artifacts; immutable topology, rig/deformation,
skin-integrity, ground-contact, object-contact, and clothed-visual proof; and
Robert's immutable exact-build clothed in-motion approval. Aliases and variants
of one subject count once. A pass permits only a one-at-a-time dry-run
authoring schedule. It cannot queue, generate, activate, replace, publish, or
auto-approve a later body. The current state is locked at zero of two.
