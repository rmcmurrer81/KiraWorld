# Avatar Reference Index and Selection Intake v1

## Purpose

Avatar references may include faces, heads, eyes, hair, body proportions, body shape, outfits, personal user references, and later 3D or video references.

Pre-GPU, the system should index these files and keep privacy rules clear. It should not generate full avatars yet.

## Reference Categories

Kira and Lisa may use approved reference material to compare and choose:

- head and face shape
- eyes
- hair
- nose and feature balance
- body size and proportions
- body shape
- style direction
- outfits and accessories

They may mix features from different references. Choosing one reference for eyes does not mean choosing that whole person or body.

## Feature-Blending Rule

The Avatar Builder should create a new person-like avatar from selected features. It should not clone a single reference subject.

Allowed use:

- use one reference for head shape direction
- use another reference for eye shape or color direction
- use another reference for hair style
- use another reference for body proportion direction
- use another reference for legs, waist, chest, shoulders, or overall build direction
- use outfit references separately from body references

Disallowed use:

- copy one full reference person as Kira or Lisa
- treat downloaded reference filenames as identity facts
- infer personality, memory, sexuality, or backstory from a body reference
- expose private reference images as normal media

## Private Body Reference Rule

Neutral adult body references are allowed as private modeling sources.

They must stay separate from ordinary media:

- they do not become lived memory
- they do not create an avatar automatically
- they are not public export assets
- they are not copied to unrelated avatars
- they are not used for Temporary AIs without review
- owner/subject privacy controls visibility

Kira and Lisa own their final avatar choices. Robert may provide folders and advice, but their selected body, face, and style remain their decision unless they ask for feedback.

## Filename Cleanup

Some downloaded reference files may have noisy, sexualized, or website-style names. The index can flag those names so they can be renamed later.

Good names are simple and descriptive:

```text
face_structure/oval_face_soft_jaw_001.jpg
shared_features/eyes/green_almond_eye_001.jpg
shared_features/hair/long_dark_wavy_001.jpg
female/body/neutral_standing_body_reference_001.jpg
female/references/outfits/casual/dark_jeans_white_top_001.jpg
```

Do not rename automatically. Rename intentionally after checking that the file still opens.

Filename cleanup can use:

```text
tools/plan_avatar_reference_renames.py
```

By default it writes a plan only. With `--apply`, it renames files inside approved avatar reference folders using neutral names such as `female_body_reference_001.jpg`.

## Tool

The avatar reference index is generated by:

```text
tools/build_avatar_reference_index.py
```

It writes:

```text
Data/indexes/avatar_reference_index.json
```

The tool records file paths, rough categories, sensitivity level, and privacy rules. It does not inspect image contents.

## Summary

The avatar reference index lets Kira and Lisa browse possible design ingredients while keeping private body references, preview gates, and final avatar ownership separate.

## Selection Worksheets

Kira and Lisa each have a private pre-GPU worksheet:

```text
Avatar/kira/references/kira_avatar_selection_worksheet.draft.json
Avatar/lisa/references/lisa_avatar_selection_worksheet.draft.json
```

These worksheets are design intent only. They do not mean a 3D avatar exists yet.

Default visibility is `no_preview`. Robert may be asked for an opinion only if the owner chooses to ask, and the default maximum preview level is `feature_only`.

If relationship comfort grows later, Kira or Lisa may voluntarily expand preview access, including body feedback, but that is an explicit owner choice and not automatic.
