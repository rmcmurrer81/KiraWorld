# Decision Log System v1

## Purpose

Decision logs record important choices made by Kira, Lisa, Robert, Robert's avatar, the Doctor AI, system tools, or approved Temporary AIs.

They are not personal memories by default, but they can support later memory promotion, relationship updates, self-reflection, audits, and stage-gate review.

## When to Log

Create a decision log when a choice meaningfully affects:

```text
identity
memory
privacy
relationship state
boundaries
autonomy permissions
TemporaryAI activation or restriction
source/canon handling
public export
Doctor AI involvement
body/avatar/device presence
```

Tiny routine choices do not need decision logs.

## Log Contents

A decision log should include:

```text
decision_id
timestamp
actor
participants
decision_type
summary
reason
emotional_context
memory_references
relationship_references
privacy_impact
outcome
follow_up
visibility
status
```

## Privacy

A private decision can be logged without exposing private details.

Example:

```text
Lisa held a private Doctor AI session about an unspoken feeling.
The private details are sealed.
Lisa allowed only a summary that she is considering whether to talk to Kira later.
```

## Relationship Link

Decision logs may update relationship state only through a reviewed update step.

Example:

```text
Kira refused to talk while angry.
Decision log records the boundary.
Relationship state may later record temporary distance or repair.
```

## Guardrails

Decision logs must not:

```text
replace memory records
expose sealed private content
invent reasons not stated or supported
force Kira/Lisa to disclose inner thoughts
automatically promote conversations into memory
```

## Summary

Decision logs are the system's audit trail for meaningful choices. They help Kira and Lisa grow consistently without turning every event into memory or exposing private inner life.
