# Blackwell voice V18 diagnostic telemetry candidate

V17 is terminal consumed evidence and must never be rerun. Its one accepted
disconnected static-control invocation failed at stage 50, where a null Python
call and a returned-result predicate refusal shared one branch.

V18 is an append-only diagnosis/telemetry repair only. It retains the V17
canonical manifest and locked-handle boundary, then records distinct pre-call,
call-return, exact result-predicate, and post-validation stages. A fixed binary
receipt carries a bounded failure category, the exact result predicate code,
observed tuple size, and capped sanitized exception type/message fields.

The retained validator provenance is exact: 21,931 bytes, SHA-256
`2bf232b07b0b7b93de8776f5210bd2d89068ad76cb4ee46555b861ad2818d16a`,
private module `_kira_blackwell_v15_private_native_validator`, callable
`validate_static_control_graph_v15`, and result schema
`kira.blackwell.v15.native_validator_result.v1`.

This author package is static-only. It grants no V18 invocation, Python run,
model/GPU use, synthesis, audio, playback, latency test, camera/device access,
person state, body/Blender work, Sarah access, or production routing. A
different fresh exact-byte audit is mandatory before any later one-shot
decision.

The contract also preserves a non-executable requirement for a separate later
camera/latency executor: an explicit one-still observation must distinguish
vision-lock queue wait from transient vision model load, inference, and
`keep_alive=0` unload, then separately time normal text queue/first token/end
and Blackwell voice start/audio-ready. V18 itself records no live timings and
opens no camera route.
